# [ST-006] Kite Connect app + daily login
[← index](../TECH_DEBT.md)

**Facts checked 2026-10-16:**
- The access token expires at 6 AM the next day (regulatory; kite.trade/docs/connect/v3/user), so one login a day:
  Kite login page -> redirect URL with a one-time `request_token` (valid minutes) -> POST `/session/token` with
  checksum SHA-256(api_key + request_token + api_secret) -> `access_token`.
- Static IP (SEBI, enforced 2026-04-01) is checked on **order endpoints only**; login, profile, holdings, margins work
  from any IP. So ST-006 runs on rkneo50q without ST-007.
- Pricing: **Personal is free** (orders, GTT, alerts, margins, portfolio; no market data); Connect Rs 500/month only
  adds live and historical data. stratrad uses its own EOD NSE data.
- Rakesh already has a developer account with a Personal app "Zerodha Integration" (2025-08-18, redirect
  `http://127.0.0.1:5000/...`).

**Design (Rakesh, 2026-10-16):**
1. **Plan: Personal (free).** A **separate app for stratrad** (own API key/secret; the existing app untouched). Key and
   secret only in prod `.env` (`KITE_API_KEY`, `KITE_API_SECRET`).
2. **Daily login is manual** (not automated with password + TOTP: a daily human login is the regulation's intent and is
   Rakesh's daily "trade today"). Rakesh opens a bookmarked Kite login link on his phone, logs in with password + TOTP.
3. **Callback: option B** -- a new public hostname on the existing Cloudflare tunnel to rkneo50q, behind **Cloudflare
   Access** (only Rakesh's email), routed to a small stratrad callback service on rkneo50q (localhost only). It
   exchanges the `request_token` and stores the session. Separate hostname and service; MyInvestIQ's routes unchanged.
   Not chosen: A (Tailscale-only page; needs a cert and the phone on Tailscale), C (copy the token by hand daily).
   Cloudflare sees the one-time `request_token` at its edge; useless without the secret, which never leaves rkneo50q.
4. **Session** in `~/.stratrad/kite_session.json` (mode 600, outside the repo and the mirror) with its issue time;
   each login written to `audit_log` without the token.
5. `core/kite.py`: returns a ready client, or refuses ("login needed") when there is no session or it was issued before
   today's 06:00 IST. Never prints or logs a token or secret (CLAUDE.md).
6. `scripts/kite_check.py`: read-only -- masked user id, available equity funds, number of holdings.
7. No reminder until ST-011 (Telegram): a day without a login is a day without trading.

**Built 2026-10-16 (laptop, 141 tests pass):** `core/kite.py` (thin `requests` client instead of the `kiteconnect`
library: four read-only calls, no websocket stack, easier to audit for token hygiene; a proxy for ST-007 is one setting),
`execution/kite_callback.py`, `scripts/kite_check.py`, `deploy/systemd/stratrad-kite-callback.service`,
`tests/test_kite.py` (19: 06:00 IST expiry, checksum, Access header, no token in logs/pages/repr, no order endpoint).

**Needs from others:** homelab project -- the Cloudflare hostname + Access policy (brief to follow); Rakesh -- create the
stratrad app once the hostname exists (its redirect URL is that hostname).

**Done when:** after a phone login, the session is stored and `kite_check` shows profile, funds and holdings on prod;
the next day, before a new login, `kite_check` refuses with "login needed"; the callback is unreachable without
Cloudflare Access; a search of logs, `audit_log` and the repo finds no token or secret; the code calls no order endpoint.
**Fail if:** a token or secret appears anywhere outside prod `.env` and `~/.stratrad`, a stale session is accepted, or the
callback answers without Access.
