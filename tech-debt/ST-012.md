# [ST-012] Project database + read-only role on MyInvestIQ DB
[← index](../TECH_DEBT.md)

**Scope (Rakesh, 2026-10-15):** split in two. ST-012 = the `stratrad` database; the corporate-action merge moves to
**ST-020** (blocked by MyInvestIQ TD-251, still Open: their `corporate_actions` last fetched 2026-08-28).

**Design (Rakesh, 2026-10-15; data model approved 2026-10-14, docs/DATA_MODEL.md section 4):**
1. Database `stratrad` on the existing PostgreSQL 16 (rkneo50q, localhost:5432; server timezone IST). Roles:
   `stratrad_app` (owner, the live system), `stratrad_reader` (read-only), and on MyInvestIQ's `portfolio_watch`
   `stratrad_ro` (SELECT on `corporate_actions` and `fii_daily_flow` only). Rakesh runs one superuser block
   (`database/setup_roles.sql`); passwords only in prod `.env`.
2. Migrations: `database/migrations/NNN_*.sql`, applied by `python -m scripts.migrate`, recorded in
   `schema_migrations` with a checksum; never re-applied; an applied file that changed is refused.
3. **Migration 001 creates all 14 tables of the approved model** (Rakesh: migrate all), with types, constraints and
   indexes; `audit_log` append-only by trigger; strategy `manual` seeded.
4. `core/db.py`: connections (psycopg 3); every session in UTC.
5. Research outputs (universe, sectors, features) stay files, read directly (Rakesh) -- nothing loaded each morning.
6. Raw broker payloads (`jsonb`) kept indefinitely (< 10 MB a year).
7. Backup: `pg_dump` of `stratrad` in the nightly 23:30 chain (homelab project); one test restore.

**Done when:** on prod `stratrad` exists with `stratrad_app`, `stratrad_reader` and (on `portfolio_watch`)
`stratrad_ro`; `migrate` applies 001 once and a second run changes nothing; `scripts/check_database.py` passes:
all 14 tables present, `stratrad_reader` can read but every write attempt fails, `stratrad_ro` reads
`corporate_actions` and `fii_daily_flow` and fails on any other `portfolio_watch` table and on any write, an UPDATE
or DELETE on `audit_log` fails, sessions report UTC; a test row survives `pg_dump` -> restore into a scratch database;
the nightly dump of `stratrad` appears in the backup chain (homelab confirms).
**Fail if:** any role can write where it should not, a migration runs twice, or a restore loses data.

**Moved to ST-020 (2026-10-15):** merge MyInvestIQ's `corporate_actions` table (from 2025-08-26) with
stratrad's `history.csv` in `core/corporate_actions.py`; MyInvestIQ wins on the same (symbol, ex_date, type).
Include a freshness check (fail if MyInvestIQ's newest `fetched_at` is older than 2 days) so a stopped MyInvestIQ
job cannot leave splits silently unadjusted. Needed before ST-010's held-out check and before any live signal.
**Depends on MyInvestIQ TD-251** (raised 2026-10-11): daily fetch + backfill from 2025-08-26. Until then
2025-08-26..28 is in neither source (their table starts 2025-08-29; ours ends 2025-08-25) — the merge must check
the seam has no gap.

**Done when:** to be written when the design is agreed (observable behaviour + a falsifying clause).
