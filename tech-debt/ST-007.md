# [ST-007] Mumbai VM order gateway (static IP, Tailscale)
[← index](../TECH_DEBT.md)

Scope to be proposed before work starts. See the plan doc.

**Notes from ST-006 (2026-10-16):**
- SEBI's static-IP rule (enforced 2026-04-01) applies to Kite **order endpoints only**; Zerodha allows a primary and an
  optional secondary IP per developer account, shared by all its apps.
- rkneo50q's Tailscale address (100.x) cannot serve: it is private; Kite sees the home connection's public IP, which is
  dynamic (Airtel fibre; Airtel's box bridged, Rakesh's own router dials and holds the IP).
- A home static IP from Airtel was considered and **ruled out by Rakesh** (Airtel's static IP is unreliable).
- Idea to propose here (not decided): instead of an order gateway running stratrad code on a Mumbai VM, a **static-IP
  exit** -- a small VM with a proxy reachable only over Tailscale and allowed only to Kite's API host; stratrad stays on
  rkneo50q and sends only order calls through it (pykiteconnect supports a proxy). TLS runs end to end to Kite, so the VM
  never sees tokens, keys or orders, and holds no code, secrets or database.

**Done when:** to be written when the design is agreed (observable behaviour + a falsifying clause).
